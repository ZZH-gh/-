## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YAML source file → build_packs.py | YAML 源文件由开发者编写，不可视为完全可信——可能含恶意 YAML 标签或结构错误 |
| build_packs.py → filesystem | 编译脚本写入 knowledge_packs_compiled/ 目录，路径由脚本构造，不接受外部输入 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Tampering / RCE | build_packs.py compile_pack() YAML 解析 | mitigate | 使用 yaml.safe_load() 而非 yaml.load()，防止通过 YAML 标签执行任意 Python 代码。PyYAML 6.0.3 的 safe_load 仅解析基本 YAML 结构，不处理 !!python/object 等危险标签。在 compile_pack 函数中 hardcode safe_load 调用，不在代码路径中提供切换到 unsafe loader 的选项。 |
| T-1-02 | Tampering (Path Traversal) | build_packs.py main() 路径构造 | mitigate | 所有路径使用 Path(__file__).parent.resolve() 派生，不接受命令行参数或环境变量指定路径。source_dir 和 output_dir 硬编码相对于项目根目录，不包含用户可控的路径段。 |
| T-1-03 | Tampering (Data Integrity) | build_packs.py compile_pack() 输出 | mitigate | 编译输出仅来自 Pydantic model_dump() 结果。Pydantic v2 的 extra="forbid"（默认）行为拒绝 YAML 中未在模型中定义的额外字段，防止意外数据进入编译产物。JSON 写入使用 json.dump 标准库，不引入注入向量。 |
| T-1-04 | Information Disclosure | build_packs.py 错误信息 | accept | 编译错误信息包含字段名和文件路径，用于开发者调试。这些信息仅在开发机构器上可见，不出现在分发的 exe 中。无 PII 或敏感数据风险。 |
| T-1-05 | Denial of Service | build_packs.py _check_tree_cycles() | mitigate | BFS 遍历使用 visited set 限制每个节点最多访问一次，深度上限 depth <= 10（Pydantic Field(ge=1, le=10) 约束），防止恶意构造的超大树或循环树导致编译超时。YAML 源文件在版本控制中，开发者审查后才进入编译。 |
| T-1-SC | Tampering | pip install 依赖 | accept | Phase 1 不安装新包。PyYAML 6.0.3 和 pydantic 2.12.5 已在开发环境中安装，Package Legitimacy Audit 表确认两者均为 [OK] 状态。 |
</threat_model>
