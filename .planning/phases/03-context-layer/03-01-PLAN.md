<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User Input -> SessionState | User-provided text enters ConversationTurn.content via SessionManager.add_turn(). Text is stored as-is; no validation/sanitization at this layer because Phase 5 generator treats it as untrusted local text. |
| SessionState -> Daemon Thread | Session snapshot crosses thread boundary via copy.deepcopy(). The snapshot is an independent copy -- no shared mutable state between main thread and daemon thread. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Spoofing | SessionManager.create_session() | accept | uuid4 provides 122 random bits. Collision probability is essentially zero for a single-user desktop app creating one session per interaction. The session_id is an in-process key only, never exposed externally. No mitigation needed. |
| T-3-02 | Tampering | SessionState.extracted_info | mitigate | extracted_info values are set by Phase 4 conversation engine (trusted code), not directly from raw user input. If Phase 4 ever passes raw user input as extracted_info values, risk is still negligible -- the data is consumed locally by Phase 5 prompt generator with no network transmission. Mitigation: update_extracted_info() docstring documents that callers should sanitize values before storing. |
| T-3-03 | Denial of Service | SessionManager.add_turn() | accept | No limit on number of turns. A buggy caller could append excessive turns, consuming memory. In practice, CONV-04 (3-question hard limit in Phase 4) caps turns at ~8 per session, and the desktop app creates one session per user interaction. Accepting this risk -- adding a turn limit would be premature optimization. |
| T-3-04 | Information Disclosure | SessionManager.get_session_snapshot() | mitigate | Deepcopy creates independent copy with no shared references. D-06 invariant: session is frozen during generation, so snapshot data is stable. If a bug causes a daemon thread to call get_active_session() (live reference) instead of get_session_snapshot(), the daemon thread could read mutating data. Mitigation: get_active_session() docstring explicitly warns "for main thread only"; get_session_snapshot() docstring states "for daemon threads -- returns independent deepcopy." |
| T-3-05 | Elevation of Privilege | ContextBuilder.build_generation_context() | accept | ContextBuilder reads from knowledge_manager (local filesystem reads) and session state (in-memory). No privilege boundary crossed. The function is pure -- no side effects, no file writes. |
| T-3-SC | Tampering | npm/pip/cargo installs | accept | Phase 3 installs zero external packages. All code uses Python stdlib only (uuid, time, copy, typing). No supply chain risk. |
