**Step B: 新增 10 棵追问树（在现有 follow_up_trees 区域追加）**

每棵树使用 YAML 格式，结构严格遵循 Research.md Pattern 5。每棵树要求：

- `task_type`: 与 tasks 中 follow_up_tree 字段值精确匹配
- `root_node_id`: 根节点 ID（格式：`{task_type}_q1`）
- `nodes`: dict of node_id → QuestionNode

每个 QuestionNode 必须包含：
- `node_id`: 唯一标识符
- `question_text`: 追问的问题文本（中文）
- `question_type`: "single_choice" / "multi_choice" / "text_input" / "confirm"
- `info_key`: 该问题映射的上下文信息键名
- `depth`: 节点深度（1-10）
- `options`: 至少 2 个选项（对于 single_choice/multi_choice 类型），每个 option 有 value+label
- `children`: 选项值到子节点 ID 的映射
- `fallback_node_id`: 用户说"不知道"时的降级节点（可为 null，根节点必须有 fallback）
- `is_leaf`: 是否为叶子节点（depth >= 4 的节点建议标记为 leaf）

**质量约束（场景级——per QA-01 标准）：**
1. 每棵树 5-8 个节点（`5 <= len(nodes) <= 8`）
2. 至少 2 个节点的 children >= 2 个条目（分支覆盖）
3. 至少 2 个节点的 fallback_node_id 非 null（降级路径）
4. 至少 1 个节点的 is_leaf: true（终端节点）
5. root_node_id 对应的节点存在于 nodes 中
6. 所有 children 引用的 node_id 在 nodes 中存在（引用完整性）
7. 无自引用（children 值不等于自身 node_id）
8. depth >= 2 的节点优先使用 multi_choice/text_input（深化问题），depth 1 节点优先使用 single_choice（引导）
