## Summary

Phase 2 builds the runtime knowledge layer that bridges the gap between the Phase 1 compilation pipeline and the v4.0 application logic. Three new modules are created: `KnowledgeManager` (singleton, lazy-loader, industry matcher), `KnowledgePack` (typed wrapper around raw JSON dicts), and a `follow_up_tree` traversal utility. The existing `build_packs.py` is extended to auto-generate a lightweight `index.json` (~5KB) from all compiled packs. The existing `engine.py` `_identify_industry()` is replaced by `KnowledgeManager.match_industry()`, which uses the same keyword weight scoring pattern but operates on the index rather than the v3.0 `knowledge.py` dict. The Internet/IT knowledge pack YAML is expanded from 36 terms/5 scenarios to 80+/15+/3+ per KNOW-04.

No new runtime dependencies are needed. All Phase 2 code uses Python stdlib: `json`, `pathlib`, `collections.OrderedDict`, `typing.NamedTuple`. The existing fallback `knowledge.py` remains untouched and is used only when compiled JSON loading fails.

**Primary recommendation:** Implement `KnowledgeManager` as a module-level singleton (matching the `default_engine` pattern from `engine.py`), using `collections.OrderedDict` for the LRU-2 cache. `KnowledgePack` is a thin wrapper class that provides typed getter methods (`get_terms()`, `get_workflows()`, `get_follow_up_tree()`, etc.) but internally stores raw `dict`/`list` from `json.load()`. Extend `build_packs.py` with a `_generate_index()` function that runs after all packs compile successfully.

### Pattern 1: KnowledgeManager Singleton with LRU-2 Cache

**What:** A module-level singleton that manages the lifecycle of knowledge pack data. On app startup, it loads only the lightweight index. On industry confirmation, it loads the full pack JSON via LRU-2 cache.

**When to use:** This pattern is the central data access point for all runtime knowledge. Every component that needs industry-specific data goes through the KnowledgeManager.

**Key design points:**
- Module-level singleton: `knowledge_manager = KnowledgeManager()` at module bottom, matching `engine.py`'s `default_engine` pattern [VERIFIED: codebase architecture]
- `initialize()` loads index.json using `pathlib.Path` relative to `__file__`, supporting both development (direct Python) and production (PyInstaller bundled) paths
- `load_pack(industry_id)` checks LRU cache first, loads from disk on miss, evicts oldest on overflow
- `match_industry(user_input)` operates on index keywords only -- no full pack needed for matching
- All methods assume single-threaded access (D-08). No locks. Dict assignment is atomic in CPython.

**LRU cache implementation using OrderedDict:**

```python
from collections import OrderedDict

class KnowledgeManager:
    def __init__(self):
        self._index: dict[str, dict] = {}       # industry_id -> index entry
        self._cache: OrderedDict[str, KnowledgePack] = OrderedDict()
        self._max_cache_size = 2
        self._initialized = False
        self._fallback_active = False
        self._compiled_dir: Path | None = None
    
    def initialize(self):
        """Load index.json from compiled directory. Called once at app startup."""
        self._compiled_dir = Path(__file__).parent / "knowledge_packs_compiled"
        index_path = self._compiled_dir / "index.json"
        try:
            with open(index_path, "r", encoding="utf-8") as f:
                self._index = json.load(f)
            self._initialized = True
        except (FileNotFoundError, json.JSONDecodeError):
            self._fallback_active = True
            # Fallback: build index from knowledge.py INDUSTRIES
            self._build_fallback_index()
    
    def load_pack(self, industry_id: str) -> "KnowledgePack":
        """Load a knowledge pack. Returns cached version if available."""
        if industry_id in self._cache:
            self._cache.move_to_end(industry_id)
            return self._cache[industry_id]
        
        pack = self._load_from_disk(industry_id)
        
        if len(self._cache) >= self._max_cache_size:
            self._cache.popitem(last=False)  # evict oldest
        
        self._cache[industry_id] = pack
        return pack
    
    def _load_from_disk(self, industry_id: str) -> "KnowledgePack":
        """Load JSON from disk, fallback to knowledge.py if fails."""
        pack_path = self._compiled_dir / f"{industry_id}.json"
        try:
            with open(pack_path, "r", encoding="utf-8") as f:
                data = json.load(f)
            return KnowledgePack(data)
        except (FileNotFoundError, json.JSONDecodeError):
            self._fallback_active = True
            return self._build_fallback_pack(industry_id)
```

**LRU-2 rationale:** Two slots -- one for the current industry, one for the previously used industry. Switching between two industries is the most common pattern (user compares or switches). The OrderedDict `move_to_end()` on access implements the "recently used" tracking. `popitem(last=False)` evicts the least-recently-used entry.

Source: Python `collections.OrderedDict` docs [VERIFIED: Python 3.12 docs]

### Pattern 2: index.json Auto-Generation (build_packs.py Extension)

**What:** After all packs compile successfully, `build_packs.py` calls `_generate_index()` which iterates over every compiled JSON, extracts meta + keywords + stats, and writes `index.json`.

**When to use:** Every build cycle. Runs after all pack compilations succeed.

**Keyword extraction logic:** Collect from YAML source:
1. All `meta.keywords` -- the industry-level keyword list
2. All `terms[].term` -- every term name
3. All `terms[].aliases[]` -- every alias
4. All `tasks[].name` -- every task/scenario name
5. All `tasks[].task_keywords` from the v3.0 equivalent (if converting from knowledge.py) or from the YAML task description text

This gives a rich keyword set for matching without loading the full pack.

**Implementation in build_packs.py:**

```python
def _generate_index(output_dir: Path) -> dict:
    """Generate index.json from all compiled JSON packs.
    
    Called by main() after all packs compile successfully.
    Returns the index dict (also written to output_dir/index.json).
    """
    index = {}
    for json_path in sorted(output_dir.glob("*.json")):
        if json_path.name == "index.json":
            continue
        with open(json_path, "r", encoding="utf-8") as f:
            pack = json.load(f)
        
        meta = pack.get("meta", {})
        pack_id = meta.get("id", json_path.stem)
        
        # Collect keywords from terms, tasks, and meta
        keywords = []
        for term in pack.get("terms", []):
            keywords.append(term.get("term", ""))
            keywords.extend(term.get("aliases", []))
        for task in pack.get("tasks", []):
            keywords.append(task.get("name", ""))
        # Also include industry-level keywords if the YAML meta has a keywords list
        # (currently not in schema, but can be added to meta section)
        
        # Deduplicate and filter empty
        keywords = sorted(set(k for k in keywords if k))
        
        index[pack_id] = {
            "id": pack_id,
            "name": meta.get("name", pack_id),
            "icon": meta.get("icon", ""),
            "description": meta.get("description", ""),
            "keywords": keywords,
            "pack_file": json_path.name,
            "stats": {
                "term_count": len(pack.get("terms", [])),
                "scenario_count": len(pack.get("tasks", [])),
                "tree_count": len(pack.get("follow_up_trees", [])),
                "role_count": len(pack.get("roles", [])),
                "workflow_count": len(pack.get("workflows", [])),
            }
        }
    
    # Write index.json
    index_path = output_dir / "index.json"
    with open(index_path, "w", encoding="utf-8") as f:
        json.dump(index, f, ensure_ascii=False, indent=2)
    
    print(f"\n  Generated index.json with {len(index)} industry entries")
    return index
```

**Integration into main():** Call `_generate_index()` after the success loop, before the final "All packs compiled" message. If index generation fails (unlikely), it should print a warning but not fail the build -- index.json is a derived artifact, not a pack.

### Pattern 3: KnowledgePack Wrapper Class (dict + getters, no Pydantic)

**What:** A thin wrapper around the raw `dict` from `json.load()`. Provides typed getter methods that return native Python types (list, dict, str, None). No validation at runtime -- assumes data is valid because compile-time validation caught all errors.

**When to use:** Every time a consumer needs data from a loaded knowledge pack. Generator (Phase 5), conversation engine (Phase 4), and UI (Phase 6) all access pack data through this interface.

```python
class KnowledgePack:
    """Typed wrapper around a compiled knowledge pack JSON dict.
    
    All data is loaded at construction time. Methods provide typed access
    to specific slices of the data. Returns native Python types only.
    No Pydantic, no validation -- assumes pre-validated data.
    """
    
    def __init__(self, data: dict):
        self._data = data
    
    def get_meta(self) -> dict:
        """Returns meta dict with id, name, icon, description, etc."""
        return self._data.get("meta", {})
    
    def get_terms(self, category: str | None = None) -> list[dict]:
        """Returns all terms, optionally filtered by category.
        
        Each term has keys: term, category, definition, aliases,
        usage_context, related_terms.
        """
        terms = self._data.get("terms", [])
        if category:
            return [t for t in terms if t.get("category") == category]
        return terms
    
    def get_task(self, task_name: str) -> dict | None:
        """Returns a single task by name, or None if not found."""
        for task in self._data.get("tasks", []):
            if task.get("name") == task_name:
                return task
        return None
    
    def get_tasks(self) -> list[dict]:
        """Returns all task/scenario definitions."""
        return self._data.get("tasks", [])
    
    def get_roles(self) -> list[dict]:
        """Returns all role definitions with KPIs, pain_points, etc."""
        return self._data.get("roles", [])
    
    def get_role(self, role_name: str) -> dict | None:
        """Returns a single role by name."""
        for role in self._data.get("roles", []):
            if role.get("name") == role_name:
                return role
        return None
    
    def get_workflow(self, name: str) -> dict | None:
        """Returns a workflow by name, with steps, decision_points, failure_modes."""
        for wf in self._data.get("workflows", []):
            if wf.get("name") == name:
                return wf
        return None
    
    def get_workflows(self, category: str | None = None) -> list[dict]:
        """Returns all workflows, optionally filtered by category."""
        wfs = self._data.get("workflows", [])
        if category:
            return [w for w in wfs if w.get("category") == category]
        return wfs
    
    def get_doc_template(self, template_name: str) -> dict | None:
        """Returns a doc template by name."""
        for doc in self._data.get("docs", []):
            if doc.get("name") == template_name:
                return doc
        return None
    
    def get_doc_templates(self, task_type: str | None = None) -> list[dict]:
        """Returns doc templates, optionally filtered by task_type."""
        docs = self._data.get("docs", [])
        if task_type:
            return [d for d in docs if d.get("task_type") == task_type]
        return docs
    
    def get_follow_up_tree(self, task_type: str) -> dict | None:
        """Returns a follow-up tree by its task_type identifier.
        
        Returns: {
            "task_type": str,
            "root_node_id": str,
            "nodes": {node_id: {...}, ...}
        }
        """
        for tree in self._data.get("follow_up_trees", []):
            if tree.get("task_type") == task_type:
                return tree
        return None
    
    def get_pain_points(self) -> list[dict]:
        """Returns all industry pain points."""
        return self._data.get("pain_points", [])
```

**Key design decisions:**
- No `__getitem__` dict-style access -- forces consumers to use named methods
- Optional `category` parameter on list methods for filtering, consistent across getters
- Returns `None` for not-found single items, empty `[]` for not-found lists (consistent with v3.0 pattern)
- The `data` dict is stored as-is, no deep copy -- read-only access is safe without copying

### Pattern 4: Industry Matching (porting _identify_industry logic)

**What:** The keyword weight scoring algorithm from `engine.py` `_identify_industry()` (engine.py:135-176) is ported to `KnowledgeManager.match_industry()`. The logic is identical but operates on index keywords instead of `knowledge.py` INDUSTRIES keywords.

**When to use:** Every time the user types input and clicks generate. Called before the industry is identified.

```python
from typing import NamedTuple

class IndustryMatch(NamedTuple):
    industry_id: str
    industry_name: str
    score: float

class KnowledgeManager:
    # ... (initialize, load_pack, etc.) ...
    
    def match_industry(self, user_input: str) -> list[IndustryMatch]:
        """Score all industries against user input, return ranked list.
        
        Uses the same keyword weight scoring as v3.0 _identify_industry():
        - Exact match: +3 per keyword
        - Case-insensitive match: +2 per keyword
        - Substring/bigram match: +1 per keyword
        
        Returns sorted list of IndustryMatch tuples, highest score first.
        Empty list if no matches (caller handles fallback to "通用").
        """
        if not self._initialized and not self._fallback_active:
            return []
        
        text_lower = user_input.lower()
        scores: dict[str, float] = {}
        
        for industry_id, entry in self._index.items():
            score = 0.0
            keywords = entry.get("keywords", [])
            
            for kw in keywords:
                if not kw:
                    continue
                kw_lower = kw.lower()
                
                if kw in user_input:
                    score += 3.0
                elif kw_lower in text_lower:
                    score += 2.0
                # Simple substring check for Chinese multi-char matches
                elif len(kw) >= 2 and kw in text_lower:
                    # This handles cases where user input "写PRD" matches keyword "PRD"
                    # by checking if any keyword is contained in the input text
                    pass  # already handled by direct match above
            
            if score > 0:
                scores[industry_id] = score
        
        # Sort descending by score
        ranked = sorted(
            [IndustryMatch(iid, entry["name"], s) for iid, entry in self._index.items() if s > 0],
            key=lambda m: m.score,
            reverse=True
        )
        
        return ranked
```

**Integration with engine.py:**

```python
# In engine.py __init__

Rather than adding complex fallback logic inside engine.py, the cleaner boundary is: KnowledgeManager owns the index and matching, engine.py calls it. This follows the single-responsibility principle and keeps engine.py simpler.

### Pattern 6: Fallback to v3.0 knowledge.py

**What:** If compiled JSON loading fails (file missing, corrupted, or wrong format), the KnowledgeManager silently falls back to wrapping the existing `knowledge.py` `INDUSTRIES` dict in a KnowledgePack-compatible adapter. The status bar shows a warning but the app continues working with v3.0 data.

**When to use:** Only on load failure. The fallback is transparent to downstream consumers -- they call the same `KnowledgePack` interface either way.

```python
from .knowledge import INDUSTRIES

class _KnowledgePackFallback(KnowledgePack):
    """Adapter wrapping v3.0 knowledge.py INDUSTRIES dict as a KnowledgePack."""
    
    def __init__(self, industry_key: str):
        industry = INDUSTRIES.get(industry_key, {})
        self._meta = {
            "id": industry_key,
            "name": industry.get("name", industry_key),
            "icon": industry.get("icon", ""),
            "description": "",
            "version": "3.0",
            "schema_version": "1.0",
        }
        self._terms = []
        self._tasks = []
        self._roles = []
        self._workflows = []
        self._docs = []
        self._follow_up_trees = []
        self._pain_points = []
        
        # Convert templates to task-like structures for compatibility
        templates = industry.get("templates", {})
        for task_name, task_info in templates.items():
            self._tasks.append({
                "name": task_name,
                "description": task_info.get("description", ""),
                "typical_output": "",
                "complexity": "medium",
                "frequency": "medium",
                "follow_up_tree": "",
            })
```

**Note:** The fallback does not need to be a comprehensive conversion. It only needs to provide enough data for the current v3.0 feature set to work. The generator in Phase 5 is the first consumer that genuinely needs KnowledgePack data -- Phase 2's engine.py only uses `match_industry()` which operates on the index, not the full pack.

### Anti-Patterns to Avoid

- **Do NOT call `load_pack()` during `match_industry()`.** The match operates on the index alone. Loading the full pack before industry is confirmed defeats the lazy-loading purpose.
- **Do NOT put Pydantic models in KnowledgePack.** D-06 explicitly states dict + getters. Pydantic in runtime would add ~2MB to the exe and is unnecessary since data is pre-validated.
- **Do NOT assume `_initialized` is `True` in `match_industry()`.** The fallback path (`_fallback_active = True`) may be set if index.json fails to load. Always check both conditions.
- **Do NOT add threading locks.** D-08 explicitly says single-threaded. Locks would add complexity with zero benefit.
- **Do NOT modify `knowledge.py`.** The fallback reads from it. Modifying it would break the v3.0 code path.
- **Do NOT use `__file__` directly in PyInstaller context.** Use `pathlib.Path(__file__).parent` during development and handle `sys._MEIPASS` for bundled paths. The common pattern is:

```python
import sys
from pathlib import Path

def _get_resource_dir() -> Path:
    """Return the directory containing compiled knowledge packs.
    Works in both development and PyInstaller-bundled mode.
    """
    if getattr(sys, 'frozen', False):
        # PyInstaller --onedir or --onefile
        return Path(sys._MEIPASS) / "prompt_tool" / "knowledge_packs_compiled"
    else:
        return Path(__file__).parent / "knowledge_packs_compiled"
```

This pattern is well-documented in the PyInstaller manual [CITED: pyinstaller.readthedocs.io].

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| LRU cache | Custom linked list | `collections.OrderedDict` | OrderedDict provides `move_to_end()` (O(1) reordering) and `popitem(last=False)` (O(1) FIFO eviction). A custom linked list would need to track head/tail pointers and is error-prone. |
| JSON loading | Custom file parser | `json.load()` stdlib | C-optimized, handles all Unicode, embedded in every Python runtime. |
| Cross-platform path resolution | String concatenation with os.sep | `pathlib.Path` | Path objects handle Windows backslashes, forward slashes, and PyInstaller paths uniformly. |
| Confidence ranking | Sort by score manually | `sorted()` with `reverse=True` | One-liner. No need for a ranking algorithm -- simple weighted sum is sufficient for keyword matching. |

**Key insight:** Phase 2 has no deceptively complex problems. Every challenge (LRU cache, file loading, path resolution, keyword matching) is a solved problem with a stdlib or simple Python idiom solution. The hard part is the architecture design, not the implementation.

## Common Pitfalls

### Pitfall 1: PyInstaller Path Resolution at Runtime

**What goes wrong:** `Path(__file__).parent` resolves to a temporary extraction directory when running from a PyInstaller-bundled exe, not the expected project structure. KnowledgeManager tries to read from a wrong path and raises FileNotFoundError.

**Why it happens:** PyInstaller bundles data files into `sys._MEIPASS` (for `--onefile`) or alongside the exe (for `--onedir`). The `__file__` path points into the temporary extraction directory.

**How to avoid:** Use the dual-path resolution pattern shown in the Anti-Patterns section. Check `sys.frozen` flag and use `Path(sys._MEIPASS)` for exe mode. Keep both paths relative from a known base path.

**Warning signs:** `FileNotFoundError` on `knowledge_packs_compiled/index.json` when running the exe, but works when running via `python -m prompt_tool.main`.

Source: PyInstaller `sys._MEIPASS` documentation [CITED: pyinstaller.org/en/stable/runtime-information.html]

### Pitfall 2: Match Against Empty/Short User Input

**What goes wrong:** User clicks "generate" with only 1-2 Chinese characters (e.g., "写代码"). The keyword matcher assigns inflated scores because short strings match many partial keywords.

**Why it happens:** The keyword scoring algorithm uses exact match (+3) and substring match (+2). A 2-character Chinese input can match substrings of many multi-character keywords.

**How to avoid:** Apply a minimum input length threshold (>= 4 Chinese characters, or >= 2 English words) before running match_industry(). If input is too short, return empty list and let the caller use "通用" fallback. Alternatively, normalize scores by input length.

**Warning signs:** Engine consistently identifies the wrong industry when input is very short.

### Pitfall 3: Index Bloat from Keyword Explosion

**What goes wrong:** As the Internet/IT pack expands from 36 to 80+ terms, and each term's aliases are included in the index, the index grows well beyond the 5KB budget.

**Why it happens:** Each term contributes 1-5 keywords (term + 1-4 aliases). 80 terms x 3 aliases average = ~320 keywords. At ~10 bytes per keyword = ~3.2KB just for keywords. Plus JSON overhead (~50% for structure), the index could reach 10-15KB.

**How to avoid:** 
- Include term name + term aliases in index keywords, but NOT related_terms (those create cross-references that inflate the index without matching benefit)
- Include scenario names but NOT task description text
- Consider limiting aliases to 2 per term for index purposes (full aliases are in the compiled pack)
- If 5KB is exceeded, the budget can be relaxed -- the critical constraint is that the index fits in memory and loads fast (< 100ms). 15KB is still negligible.

**Warning signs:** `index.json` exceeds 50KB; startup time increases beyond 200ms.

### Pitfall 4: Fallback KnowledgePack Incompatibility

**What goes wrong:** The fallback `_KnowledgePackFallback` creates empty lists for terms/roles/workflows/etc. When Phase 5's generator calls `pack.get_terms()`, it gets an empty list instead of the rich v3.0 keyword list it expects.

**Why it happens:** The v3.0 `knowledge.py` `INDUSTRIES` dict has a completely different structure from the compiled JSON. The fallback adapter can only approximate the KnowledgePack interface.

**How to avoid:** Ensure every getter method on `_KnowledgePackFallback` returns something that the consumer can work with. For empty data, return `[]` or `{}` -- never `None` for list methods. The `get_terms()` can be populated from `INDUSTRIES[key]["keywords"]` rather than left empty. The `get_tasks()` can be populated from `INDUSTRIES[key]["templates"]`.

**Warning signs:** Phase 5 crashes on `AttributeError: 'NoneType' object has no attribute 'get'` when fallback is active.

### Pitfall 5: index.json Goes Stale

**What goes wrong:** After editing a YAML pack, a developer runs the app directly without running `build_packs.py` first. The index.json still references old keyword counts and may lack newly added terms.

**Why it happens:** index.json is a derived artifact. It is auto-generated by `build_packs.py` but only when that script runs. During development, developers often run `python -m prompt_tool.main` directly without recompiling.

**How to avoid:** Add a startup check in `KnowledgeManager.initialize()` that verifies index.json exists and has at least one entry. If not, print a clear error (not crash, but log). The `build_packs.py` integration into `build.bat` already ensures the shipped exe has fresh data. For development, document the workflow: "Run `python build_packs.py` before testing."

**Warning signs:** Newly added terms in YAML don't appear in industry matching results.

## Code Examples

### Example 1: Complete KnowledgeManager Implementation Sketch

```python
"""
Knowledge Manager - Runtime knowledge pack loader and industry matcher.

Module-level singleton: from prompt_tool.knowledge_manager import knowledge_manager

Architecture:
  - initialize() called once at app startup (by app.py)
  - Loads only index.json (~5KB) from knowledge_packs_compiled/
  - match_industry() scores user input against index keywords
  - load_pack() lazily loads full JSON, cached via LRU-2 (OrderedDict)
  - Falls back to v3.0 knowledge.py if compiled JSON unavailable
"""

import json
import sys
from collections import OrderedDict
from pathlib import Path
from typing import NamedTuple


class IndustryMatch(NamedTuple):
    """Result of an industry match attempt."""
    industry_id: str
    industry_name: str
    score: float


class KnowledgeManager:
    """Singleton runtime manager for knowledge pack lifecycle."""

    def __init__(self):
        self._index: dict[str, dict] = {}
        self._cache: OrderedDict[str, "KnowledgePack"] = OrderedDict()
        self._max_cache_size = 2
        self._initialized = False
        self._fallback_active = False
        self._compiled_dir: Path | None = None

    def initialize(self) -> None:
        """Load index.json. Call once at app startup before mainloop."""
        self._compiled_dir = self._resolve_compiled_dir()
        index_path = self._compiled_dir / "index.json"

        try:
            with open(index_path, "r", encoding="utf-8") as f:
                self._index = json.load(f)
            self._initialized = True
        except (FileNotFoundError, json.JSONDecodeError) as e:
            self._fallback_active = True
            self._build_fallback_index()
            print(f"[knowledge_manager] Fallback active: {e}")

    def match_industry(self, user_input: str) -> list[IndustryMatch]:
        """Return confidence-ranked list of matching industries."""
        if not self._initialized and not self._fallback_active:
            return []

        if len(user_input.strip()) < 2:
            return []

        text_lower = user_input.lower()
        results: list[IndustryMatch] = []

        for industry_id, entry in self._index.items():
            score = 0.0
            for kw in entry.get("keywords", []):
                if not kw:
                    continue
                kw_lower = kw.lower()
                if kw in user_input:
                    score += 3.0
                elif kw_lower in text_lower:
                    score += 2.0

            if score > 0:
                results.append(IndustryMatch(
                    industry_id=industry_id,
                    industry_name=entry.get("name", industry_id),
                    score=score,
                ))

        results.sort(key=lambda m: m.score, reverse=True)
        return results

    def get_index(self) -> dict:
        """Return raw index dict (for debug/UI display)."""
        return self._index

    def load_pack(self, industry_id: str) -> "KnowledgePack":
        """Load a knowledge pack. Uses LRU-2 cache."""
        from .knowledge_pack import KnowledgePack  # local import to avoid cycle

        # Cache hit
        if industry_id in self._cache:
            self._cache.move_to_end(industry_id)
            return self._cache[industry_id]

        # Cache miss -- load from disk
        pack = self._load_from_disk(industry_id)

        # Evict oldest if at capacity
        if len(self._cache) >= self._max_cache_size:
            self._cache.popitem(last=False)

        self._cache[industry_id] = pack
        return pack

    def get_loaded_industry_ids(self) -> list[str]:
        """Return industry IDs currently in cache."""
        return list(self._cache.keys())

    def is_fallback_active(self) -> bool:
        return self._fallback_active

    # ---- Internal ----

    def _resolve_compiled_dir(self) -> Path:
        """Return path to knowledge_packs_compiled/ in any runtime context."""
        if getattr(sys, "frozen", False):
            base = Path(sys._MEIPASS)
        else:
            base = Path(__file__).parent
        return base / "knowledge_packs_compiled"

    def _load_from_disk(self, industry_id: str) -> "KnowledgePack":
        """Load JSON from disk. Fallback to knowledge.py on failure."""
        from .knowledge_pack import KnowledgePack

        pack_path = self._compiled_dir / f"{industry_id}.json"
        try:
            with open(pack_path, "r", encoding="utf-8") as f:
                data = json.load(f)
            return KnowledgePack(data)
        except (FileNotFoundError, json.JSONDecodeError):
            self._fallback_active = True
            return self._build_fallback_pack(industry_id)

    def _build_fallback_index(self) -> None:
        """Build a minimal index from v3.0 knowledge.py INDUSTRIES."""
        from .knowledge import INDUSTRIES

        for key, industry in INDUSTRIES.items():
            keywords = list(industry.get("keywords", []))
            templates = industry.get("templates", {})
            self._index[key] = {
                "id": key,
                "name": industry.get("name", key),
                "icon": industry.get("icon", ""),
                "description": "",
                "keywords": keywords,
                "pack_file": "",
                "stats": {
                    "term_count": 0,
                    "scenario_count": len(templates),
                    "tree_count": 0,
                    "role_count": 0,
                    "workflow_count": 0,
                },
            }

    def _build_fallback_pack(self, industry_id: str) -> "KnowledgePack":
        """Build a KnowledgePack-compatible wrapper from v3.0 data."""
        from .knowledge_pack import KnowledgePack

        industry = {}
        try:
            from .knowledge import INDUSTRIES
            industry = INDUSTRIES.get(industry_id, {})
        except ImportError:
            pass

        # Build compatible data dict
        data = {
            "meta": {
                "id": industry_id,
                "name": industry.get("name", industry_id),
                "icon": industry.get("icon", ""),
                "description": "",
                "version": "3.0",
                "schema_version": "1.0",
            },
            "terms": [],
            "tasks": [
                {
                    "name": task_name,
                    "description": task_info.get("description", ""),
                    "typical_output": "",
                    "complexity": "medium",
                    "frequency": "medium",
                    "follow_up_tree": "",
                }
                for task_name, task_info in industry.get("templates", {}).items()
            ],
            "roles": [],
            "workflows": [],
            "docs": [],
            "follow_up_trees": [],
            "pain_points": [],
        }
        return KnowledgePack(data)


# Module-level singleton
knowledge_manager = KnowledgeManager()
```

# New function:
def _generate_index(output_dir: Path) -> dict:
    """Generate index.json from all compiled JSON packs."""
    index = {}
    for json_path in sorted(output_dir.glob("*.json")):
        if json_path.name == "index.json":
            continue
        with open(json_path, "r", encoding="utf-8") as f:
            pack = json.load(f)
        
        meta = pack.get("meta", {})
        pack_id = meta.get("id", json_path.stem)
        
        # Collect keywords from terms (term + aliases)
        keywords = []
        for term in pack.get("terms", []):
            t = term.get("term", "")
            if t:
                keywords.append(t)
            keywords.extend(term.get("aliases", []))
        # Add task names
        for task in pack.get("tasks", []):
            t = task.get("name", "")
            if t:
                keywords.append(t)
        
        keywords = sorted(set(k for k in keywords if k))
        
        index[pack_id] = {
            "id": pack_id,
            "name": meta.get("name", pack_id),
            "icon": meta.get("icon", ""),
            "description": meta.get("description", ""),
            "keywords": keywords,
            "pack_file": json_path.name,
            "stats": {
                "term_count": len(pack.get("terms", [])),
                "scenario_count": len(pack.get("tasks", [])),
                "tree_count": len(pack.get("follow_up_trees", [])),
                "role_count": len(pack.get("roles", [])),
                "workflow_count": len(pack.get("workflows", [])),
            },
        }
    
    index_path = output_dir / "index.json"
    with open(index_path, "w", encoding="utf-8") as f:
        json.dump(index, f, ensure_ascii=False, indent=2)
    
    print(f"  Generated index.json with {len(index)} industry entries")
    return index
```

   - What we know: Short inputs (2-4 chars) can accidentally match many keywords and score higher than intended. The v3.0 engine has the same issue.
   - What's unclear: Whether length normalization improves or degrades match accuracy for typical Chinese user inputs.
   - Recommendation: Defer to implementation. Start without normalization, add it only if testing shows poor match quality on short inputs.

2. **Where exactly should `knowledge_manager.initialize()` be called in app.py?**
   - What we know: D-12 says "before mainloop." The app.py constructor calls `_setup_ui()` then `run()` calls `mainloop()`.
   - What's unclear: Whether `initialize()` should be in `__init__()` (after `self.engine = AnalysisEngine()`) or at the top of `run()`.
   - Recommendation: In `__init__()`, after `self.engine = AnalysisEngine()` and before `_setup_ui()`. This ensures UI construction can show fallback warnings. Contribute to discretion decision.

3. **Should `get_terms(category)` filter by exact match or substring?**
   - What we know: The compiled JSON terms have a `category` field like "产品文档", "研发流程", "数据分析".
   - What's unclear: Whether filter should be exact match (category == "产品文档") or substring (category contains "产品").
   - Recommendation: Exact match. The categories are standardized in the schema. Substring filtering is a consumer concern.

4. **Should the expanded Internet/IT YAML be one file or split across multiple files?**
   - What we know: D-05 says all packs go in `knowledge_packs/`. Phase 1 has one YAML file per industry.
   - What's unclear: With 15+ scenarios and 80+ terms, a single YAML file could exceed 500KB (currently ~18KB for 36 terms/5 scenarios). Split by dimension (terms.yaml, tasks.yaml, etc.)?
   - Recommendation: Keep as one file per industry. YAML supports anchors and aliases for deduplication. The single-file pattern is simpler for content authors. If file exceeds 300KB, split in a later phase.

## Security Domain

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V5 Input Validation | Yes | `json.load()` from trusted compiled artifacts only. No user input reaches `json.load()`. The index.json is generated at build time, not from user data. |
| V5 Input Validation | Yes | `match_industry()` text input is already cleaned by `engine.py` `_clean_text()` before matching. No injection risk since there is no database or network. |

### Known Threat Patterns for Phase 2 (Runtime Data Layer)

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Malformed index.json or pack JSON | Tampering | `try/except` wrapping all `json.load()` calls. Fallback to v3.0 knowledge.py on any failure. The build pipeline is the single source of truth -- hand-edited JSON is not processed. |
| Path traversal via `industry_id` parameter | Tampering | `load_pack()` only reads from `self._compiled_dir / f"{industry_id}.json"`. The `industry_id` comes from index keys, not user input. If ever user-supplied, validate against `re.match(r"^[a-z][a-z_]*$")` (same regex as Pydantic model). |

**Key security notes:**
- Phase 2 is a pure data-layer addition. No network calls, no external input that reaches filesystem operations.
- The `load_pack()` path construction uses predefined directory + predefined filename. No user-controlled path components.
- Fallback mode degrades gracefully -- no crash, no data loss, just reduced match quality.
- Internet/IT is not a regulated industry (unlike financial/medical in future phases). No compliance content screening needed.
