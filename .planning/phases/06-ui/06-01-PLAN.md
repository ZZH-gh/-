### app_controller.py 实现规范

**类签名与初始化：**
- `AppController(on_state_change=None, on_question=None, on_results=None, on_error=None)` — 4 个可选回调参数，均为 `Callable[[dict], None]`
- 构造函数内创建 `self._engine = ConversationEngine()` 实例
- 设置 `self._is_generating = False` 并发防护标志

**方法 1: `start_session(self, user_input: str) -> None`**
- 使用已有的 `threading.Thread(target=self._do_start, args=(user_input,), daemon=True)` 模式（per PATTERNS.md Shared Patterns）
- `_do_start`: 调用 `engine.start(user_input)` → 通过 `root.after(0, ...)` 模式调度 UI 回调（注意：AppController 不持有 root 引用，改为将回调调用推到线程外部——executor 需在 `app.py` 中以 `self.root.after(0, lambda: callback(result))` 包装所有回调。AppController 内部用 `callbacks["on_X"](result)` 直接调用。）

**方法 2: `process_answer(self, answer: str) -> None`**
- 设置 `_is_generating = True`，禁用重复调用
- 后台线程调用 `engine.handle_confirmation(True)` 或 `engine.handle_answer(answer)`，根据 engine.state 决定
- 解析 engine 返回的 action dict，分发到对应回调：
  - `action == "follow_up"` → 调用 `on_question` 回调，传入 question dict（含 question_text, question_type, options, question_number, max_questions 字段）
  - `action == "generate"` → 调用 `engine.generate_complete()` → 将 prompts dict 传给 `on_results` 回调
  - `action == "clarify"` → 调用 `on_question` 回调，传入 clarify message

**方法 3: `skip_and_generate(self) -> None`**
- 调用 `engine.skip_follow_up()` → `engine.generate_complete()`
- 将生成的 prompts dict 传给 `on_results` 回调
- per D-10: 用当前已收集信息直接生成

**方法 4: `generate_complete(self) -> dict`**
- 同步方法，直接调用 `engine.generate_complete()` 返回结果 dict
- 用于当前 `_do_generate_v4` 路径的兼容（初始 auto-confirm 快速生成流程）

**方法 5: `reset(self) -> None`**
- 调用 `engine.reset()`，重置 `_is_generating = False`

**线程安全与回调调度（关键细节）：**
- AppController 在后台线程中直接调用回调（同步调用）。`app.py` 中的 PromptToolApp 负责用 `self.root.after(0, lambda: cb(data))` 包装回调函数后再传给 AppController 构造函数。这避免 AppController 需要持有 root 引用。
- 所有回调的 data 参数为 dict，包含 engine 返回的完整 action dict

### 事件处理方法

**`_on_v4_send(self)`:**
- 从 `self.v4_input.get("1.0", "end-1c").strip()` 取文本
- 如果为空或 `self._is_generating`，直接返回
- 添加用户气泡 `self._add_user_message(text)`
- 清空输入框 `self.v4_input.delete("1.0", "end")`
- 设置生成状态：`self.send_btn.configure(state="disabled", text="⏳")`，`self._is_generating = True`
- 调用 `self._v4_controller.process_input(text)`
- 注意：首次调用 process_input 时 controller 内部调用 engine.start()；后续调用为 engine.handle_confirmation()/handle_answer()

**AppController 需提供的 `process_input` 方法（在 Task 1 中已创建）：**
- 检查 engine.state：如果 IDLE → 调用 `engine.start(user_input)` + `engine.handle_confirmation(True)` → 进入 FOLLOWING_UP 流程
- 如果 FOLLOWING_UP → 调用 `engine.handle_answer(user_input)`
- 如果 CONFIRMING → 调用 `engine.handle_confirmation(True)`

**`_v4_on_question(self, data: dict)`:**
- data 包含 question dict (question_text, question_type, options, question_number, max_questions)
- 构建问题文本：`f"[{data['question_number']}/{data['max_questions']}] {data['question_text']}"`
- 调用 `_add_system_message(question_text)`
- 如果有 options 且 question_type 为 text_input：
  - 在系统消息下方添加选项提示文本（小字体灰色文本）"💡 可选：{' / '.join(o['label'] for o in options)}"
- 重置生成状态：`self.send_btn.configure(state="normal", text="▶")`，`self._is_generating = False`
- 设置状态栏：`self.set_status("💬 请回答追问或点击「立即生成」跳过")`

**`_v4_on_results(self, data: dict)`:**
- data 包含 prompts dict {"direct": str, "roleplay": str, "detailed": str}
- 保存 `self.generated_prompts = data["prompts"]`
- 调用 `self._populate_result_cards()` 填充三卡内容
- 切换到结果页面：`self._switch_to_v4_page("results")`
- 重置生成状态和按钮
- 设置状态栏：`self.set_status("✅ 已生成 3 个提示词方案")`

**`_v4_on_error(self, data: dict)`:**
- 复用现有 `_on_error` 模式：显示错误消息框，恢复按钮状态

**`_on_v4_escape(self)` — per D-10:**
- 设置 `self.send_btn.configure(state="disabled", text="⏳")`，`self.escape_btn.configure(state="disabled")`，`self._is_generating = True`
- 添加用户气泡 `self._add_user_message("🎯 立即生成")`
- 后台线程调用 `self._v4_controller.skip_and_generate()`
- controller 调用 `engine.skip_follow_up()` + `engine.generate_complete()`
- per D-10: 使用当前已收集信息直接生成

**`_on_v4_new_chat(self)` — per D-05:**
- 调用 `self._v4_controller.reset()`
- 清空 chat_scrollable 内的所有消息气泡（遍历并 destroy children）
- 重置 `self._chat_row_count = 0`
- 重新显示欢迎消息
- 切换到 chat_frame
