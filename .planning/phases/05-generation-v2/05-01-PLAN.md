## Phase Goal

**As a** 普通桌面用户, **I want to** 得到一个基于行业知识包深度合成的提示词生成器, **so that** 我输入的简短需求能被转化为包含角色深度、质量标准、输出结构和反模式警告的专业提示词。

## Plan 01 Objective

Implement the core `PromptGeneratorV2` class in `generator.py` with direct KnowledgePack loading and all four knowledge injection points (D-06: role depth, quality standards, output structure, anti-pattern warnings), then wire it into `ConversationEngine.generate_complete()` and update `app.py` per D-03/D-04 so generation flows through the ConversationEngine, not direct imports.

Purpose: Fix the critical data flow bug in the existing draft (`generator_v2.py` uses metadata-only `knowledge_pack_ref` from context_builder instead of loading the real `KnowledgePack`). Establish the foundation that Plan 02 (strategy differentiation) and Plan 03 (anti-pattern filtering) build on.

Output: `PromptGeneratorV2` class with KnowledgePack loading, knowledge selection, and 4 injection methods. Updated `ConversationEngine.generate_complete()` and `app.py` wiring.
</objective>

**Class definition: `class PromptGeneratorV2:`** — placed after the `PromptGenerator` class but before the `generate_prompts` factory.

**`__init__(self, analysis_result: dict, generation_context: dict = None)`:**

CRITICAL DATA FLOW FIX per RESEARCH.md: The existing draft (`generator_v2.py` line 33) reads `self.pack_ref = self.ctx.get("knowledge_pack_ref")` which returns `pack.get_meta()` (a metadata-only dict with `{id, name, icon, description, version}` — NO roles, NO pain_points, NO terms). This is the Phase 3 design decision to "store ID, not snapshot" but the generator must bridge this itself.

The fix: PromptGeneratorV2 loads the actual `KnowledgePack` object directly from `knowledge_manager.load_pack()`. Initialize these attributes:

- `self.r = analysis_result` (same pattern as PromptGenerator)
- `self.ctx = generation_context or {}`
- `self.industry_id = self.ctx.get("industry_id") or analysis_result.get("industry_key")`
- `self.industry_name = self.ctx.get("industry_name") or analysis_result.get("industry_name", "通用")`
- `self.task_name = self.ctx.get("task_type") or analysis_result.get("task_name", "")`
- `self.original_input = analysis_result.get("original_input", "")`
- `self.confirmed = self.ctx.get("confirmed_info", {})`
- `self.summary = self.ctx.get("conversation_summary", "")`
- `self._pack = None` — load via try/except: `self._pack = knowledge_manager.load_pack(self.industry_id)` if industry_id else None. Silently set to None on exception (handles offline/fallback mode gracefully).
- `self._task_knowledge = self._select_task_knowledge()` — cached once, shared across all 3 strategies

**`_select_task_knowledge(self) -> dict`** (D-12: task-relevant slice, not full pack):

If `self._pack is None`, return `{}` immediately.

From the KnowledgePack getter methods:
- `task = self._pack.get_task(self.task_name)` — returns dict | None
- `doc_template = self._pack.get_doc_template(self.task_name)` — returns dict | None (get_doc_template matches by name field, which corresponds to task name)
- `roles = self._pack.get_roles()` — returns list[dict]
- `pain_points = self._pack.get_pain_points()` — returns list[dict]

For role matching (D-07):
- Find role whose `common_tasks` list contains `self.task_name`: `task_role = next((r for r in roles if self.task_name in r.get("common_tasks", [])), roles[0] if roles else None)`

For terms (D-13: 8-15 terms with definitions):
- `all_terms = self._pack.get_terms()`
- Filter: terms whose `term` field appears in `task.get("keywords", [])` (if task exists), limit to 15
- Fallback: first 10 terms if no task keywords match

Return dict with:
- `"task": task`
- `"doc_template": doc_template`
- `"role": task_role`
- `"role_kpis": task_role.get("kpis", [])[:3] if task_role else []`
- `"role_pain_points": task_role.get("pain_points", [])[:2] if task_role else []`
- `"pain_points": pain_points[:3] if pain_points else []`
- `"terms": task_terms`

**Four injection methods in D-06 fixed order:**

1. **`_inject_role_depth(self) -> str`** (D-07: role with KPI + pain points, D-14: inject KPIs):
   - If no role in `self._task_knowledge`, return `""`
   - Build: `"你是一位{role['name']}。职责：{responsibilities}"` + KPI list (up to 3, format: `"- {kpi['name']}: {kpi['description']} (基准: {kpi.get('benchmark', 'N/A')})"`) + pain points note
   - Returns empty string if role is None

2. **`_inject_quality_standards(self) -> str`** (D-08: general + industry-specific):
   - Always returns content (this is the only always-on injection point)
   - General standards: "输出应包含可操作的具体步骤，而非抽象理论；内容应对标行业实际工作标准，可直接投入使用"
   - If `self._pack` exists: add industry-specific quality from pack metadata or doc template common_mistakes
   - Wrap in `"## 质量标准\n"` heading

3. **`_inject_output_structure(self) -> str`** (D-09: doc template sections):
   - If no `doc_template` with `sections` in `self._task_knowledge`, return `""`
   - Build `"## 输出结构\n"` + list of `"- {section['title']}：{section.get('prompt_hint', '')}"` for each section
   - Returns empty string if doc_template is None or has no sections

4. **`_inject_anti_patterns(self) -> str`** (D-10: pain point warnings):
   - If no pain_points in `self._task_knowledge`, return `""`
   - Build `"## 注意事项（避免以下陷阱）\n"` + list of `"- 避免{pp['name']}：{pp.get('what_not_to_do', pp.get('description', ''))}"` for up to 3 pain points
   - Returns empty string if pain_points list is empty

**Part A: Update `ConversationEngine.generate_complete()` in `conversation_engine.py`:**

The current `generate_complete()` (lines 193-196) is a stub that only transitions state and returns `{"state": ..., "action": "display_results"}` with no generation data. Rewrite it to orchestrate the full generation pipeline per D-03 and D-04.

New implementation (replace lines 193-196):

```
def generate_complete(self) -> dict:
    """Orchestrate generation: build context -> call PromptGeneratorV2 -> return result."""
    self._transition(ConversationState.GENERATING)
    
    # Build generation context from current session
    from .context_builder import build_generation_context
    from .generator import PromptGeneratorV2
    
    session = session_manager.get_active_session()
    context = build_generation_context(session) if session else {}
    
    # Instantiate generator with analysis result + context
    gen = PromptGeneratorV2(self._last_analysis, context)
    prompts = gen.generate_all()
    
    self._transition(ConversationState.COMPLETE)
    return {
        "state": self.state.value,
        "action": "display_results",
        "prompts": prompts,
    }
```

Key points:
- Transition to GENERATING before generation, COMPLETE after
- Import `build_generation_context` here (add `from .context_builder import build_generation_context` to the top imports IF NOT already present — check: it IS already imported at line 9, so no new import needed at the top)
- Import `PromptGeneratorV2` inside the method (local import avoids circular dependency at module load)
- Pass `self._last_analysis` (set by `start()`) as the analysis_result to PromptGeneratorV2
- Pass `context` dict from `build_generation_context(session)` as generation_context
- Return `prompts` key in the result dict so app.py can extract them

## Trust Boundaries

| Generation output -> Display | Prompt text displayed to user via tkinter text widget; no execution context, no HTML rendering |
