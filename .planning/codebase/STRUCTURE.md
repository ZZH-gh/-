## Directory Purposes

**`prompt_tool/`:**
- Purpose: Main application package — all source code lives here
- Contains: 6 Python files forming the complete application
- Key files:
  - `app.py` (19,121 bytes, 443 lines): Full Tkinter/customtkinter GUI with PromptToolApp class
  - `engine.py` (12,016 bytes, 329 lines): AnalysisEngine class for NLP-light input parsing
  - `generator.py` (12,657 bytes, 274 lines): PromptGenerator class for 3-strategy prompt generation
  - `knowledge.py` (39,353 bytes, 856 lines): All static data (15 industries, 12 task types, roles, formats, etc.)
  - `main.py` (909 bytes, 38 lines): Module entry point with import fallback logic
  - `__init__.py` (54 bytes): Package init comment only

**`dist/`:**
- Purpose: Build output directory (gitignored or build artifact)
- Contains: Single `.exe` file generated by PyInstaller
- Generated: Yes (by `build.bat`)
- Committed: No (build artifact)

**`.venv/`:**
- Purpose: Python virtual environment (standard pip venv)
- Contains: Python interpreter, pip, installed packages (customtkinter, pillow)
- Generated: Yes (by `python -m venv`)
- Committed: No

**`.planning/`:**
- Purpose: Planning and analysis documents used by GSD workflow tools
- Contains: Architecture, structure, and other codebase analysis documents
- Generated: Yes (by `/gsd-map-codebase` commands)
- Committed: Yes (should be -- these documents guide future development)

## Naming Conventions

**Files:**
- Snake case for all Python files: `app.py`, `engine.py`, `generator.py`, `knowledge.py`, `main.py`
- `run.py` uses short imperative name (standard PyInstaller convention)

**Classes:**
- PascalCase: `PromptToolApp`, `AnalysisEngine`, `PromptGenerator`
- No abstract base classes or protocols used

**Functions:**
- Snake case with leading underscore for private/helper methods: `_on_generate()`, `_do_generate()`, `_setup_ui()`
- Snake case for module-level public functions: `generate_prompts()`, `get_all_industry_names()`, `get_industry_key()`
- No decorators used beyond Tkinter/customtkinter event bindings

**Variables:**
- Snake case throughout: `analysis_result`, `generated_prompts`, `best_industry_key`
- Instance variables prefixed with `self.`: `self.engine`, `self.colors`, `self.input_text`
- Constants are module-level uppercase: `INDUSTRIES`, `TASK_TYPES`, `STOP_WORDS`
- Color hex values use string format: `"#2B579A"`, `"#F0F2F5"`

**Types:**
- No type hints used anywhere in the codebase (pure Python 3 with dynamic typing)
- No `typing` module imports

## Where to Add New Code

**New Feature (e.g., new strategy type):**
- Strategy definition: Add to `STRATEGIES` dict in `knowledge.py`
- Generation logic: Add method to `PromptGenerator` in `generator.py` (e.g., `_interview_style()`)
- UI tab button: Add entry to `strategies` list in `app.py` `_build_strategies_area()` (line 174-178)
- Strategy tab handler already works generically via `self.current_strategy` key lookup

**New Industry:**
- Add new industry dict to `INDUSTRIES` in `knowledge.py` following the existing schema (name, icon, keywords, templates)
- No other files need changes — the analysis and generation layers read dynamically

**New UI Component:**
- Add to `PromptToolApp` in `app.py` following the `_build_*()` pattern
- Call the new method from `_setup_ui()` and update `grid_rowconfigure` weights

**New Task Type:**
- Add to `TASK_TYPES` dict in `knowledge.py` with keywords and prompt_focus
- Optionally add to relevant industries' `templates` to get industry-specific task detection

**New Feature requiring dependencies:**
- Add to `d:\文件\提示词工具\requirements.txt`
- Add corresponding `--hidden-import` in `d:\文件\提示词工具\build.bat` if using PyInstaller

**Testing (not yet present):**
- Create `tests/` directory at project root
- Name files as `test_<module>.py` following pytest convention
- Co-locate test data fixtures in `tests/fixtures/`
